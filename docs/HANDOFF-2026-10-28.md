## pCAD follow-up — 2026-10-28

### Application name and compatibility

The displayed application, title, About text, native executable and Windows installer names are now **pCAD**. Start development with `Start-pCAD.cmd`. The local checkout folder remains `A:\Workspaces\PCBPlannerCAD`; the existing repository URL is unchanged. Internal package/storage identifiers and native format tags remain compatible with existing designs and preferences.

### Consistent via edits

The native guard now also covers pasted/arrayed vias, generic adds/changes, single and bulk properties, and move/rotate/mirror commands. It checks changed vias after dependent refill, on their full physical layer span. Rejection preserves geometry, ID allocation, dirty state and Undo/Redo history. Lock-only changes remain possible on existing invalid vias so they can be repaired. Rules off is forwarded explicitly on every edit and deliberately allows violations. Deleting a via restores its dependent pour clearance in the same undo transaction.

This check concerns added/changed vias; it is not a general rejection of every possible track, pad, rule or library edit. Full DRC remains part of final layout review.

### Connected via dragging

Dragging or picking up a via with M now keeps its same-net straight tracks attached on every spanned copper layer. The existing Preserve angles / Free / Disconnect modes apply; Disconnect remains an explicit way to leave routing behind. Traces passing through a via are split in the candidate plan so both sides follow it. A via moved off a fixed pad leaves that pad's original trace joined. Via contacts at curved-track endpoints or along their interiors keep the original curve and receive a joining route. Clockwise and wrapped sweeps are supported. Locked attached straight tracks block the move. Other nets and layers outside the via span remain fixed.

The move, track changes, teardrops and refill commit as one Route undo transaction. The via retains its ID. Delayed plans are discarded if the document or operation changes. Cancellation before placement does not mutate the board. Native connectivity tests cover multiple layers, segment interiors, via-edge contact, arc endpoints/interiors, fixed pads, multi-via rotation, locked tracks, Undo/Redo and reopen.

### Navigation changes and evidence

Net-highlight dimming is now a shader uniform. Hover changes no longer allocate tint entries for every unmarked board object. Ordinary geometry edits refit the affected branch of the picking index; membership changes and periodic rebalancing still rebuild it. Regression tests compare selections after repeated far moves with a linear oracle and cover removal and hidden-layer restoration.

Read-only measurements on a local 34,145-object board:

| CPU path | Before | After |
| --- | ---: | ---: |
| Highlighted-net hover preparation plus simulated tint update, median | 29.8 ms | 1.7 ms |
| Scene update after a small track edit, median | 63.5 ms | 2.1 ms |

The scene-update measurement excludes render-group assembly, which still took about 18 ms on that board. Cold scene preparation remains about six seconds on this fixture. These are CPU measurements, not presented FPS or a hardware requirement guarantee. GPU work, sustained native input and long routing/refill transactions still need measurement on the home laptop.

Run `pnpm.cmd -C app benchmark:navigation <absolute-native-board-path> [results.json]` for read-only CPU diagnostics. Keep real boards and output reports outside tracked source, or under the ignored `target` directory. The optional `navigation_fixture` importer example creates a new native fixture and refuses to overwrite an existing output.

### Background renderer checks

An isolated headless browser now exercises the actual renderer and shaders without attaching to existing browsers or touching the desktop. It checks normal copper, net dimming, hover override, highlight reset, unchanged overlays, high-DPI pan/zoom, WebGL errors and a dense-board render. These checks passed on this laptop, including the 34,145-object board. Browser render submission measurements exclude GPU completion/presentation; this does not certify native mouse/window behavior.

Run `pnpm.cmd -C app test:renderer [absolute-native-board-path]`. This optional check requires a Playwright installation, available either as a resolvable package or through `PCAD_PLAYWRIGHT_PATH` pointing to its package directory. On Windows the default isolated browser is Edge; `PCAD_BROWSER_EXECUTABLE` can select an installed browser executable. No copied board is embedded in the test harness.

### Local timing recorder

Help → **Record/Stop Canvas Timings** records up to 30 seconds of canvas CPU frame work and scene rebuilding. Repeat the command to finish early. Pan, zoom, select and drag during the recording. The summary appears in Messages under Performance and can be copied/saved with the existing log tools. Recording is opt-in and bounded in memory, excludes geometry/filenames, and transmits nothing automatically. CPU timings are not GPU-completion times or presented FPS; scene work may also be counted within a frame, so phase numbers must not be added together.

## Background continuation — 2026-10-28 12:38 (Europe/Bucharest)

### Connected copper and previews

- A via touching the interior of a curved trace now stays connected through a joining route, including clockwise arcs and sweeps crossing 0°. The existing curve remains exact, including a locked curve. Moving both endpoints together still transforms an unlocked curve as a whole; a locked curve blocks that transformation.
- Preserve angles reroutes instead of adjusting a locked neighboring track. Fixed far-end connections to curved copper and straight-segment interiors are retained.
- Straight-track dragging also preserves locked neighbors with a joining segment; their original geometry stays visible during preview.
- Multiple selected vias now preview interior splits even when another selected via holds a track endpoint. Curved-contact previews terminate at the moved via center, including offset edge contacts.
- M/pickup and Tab mode changes hide/restore whole-curve previews correctly. A regression verifies that a late move response cannot clear or commit over a newer preview.

### Reusing render data after edits

The scene now retains converted primitives and drawing batches for unchanged layers. Lines and fills are reused independently, so a track edit does not repack or upload unchanged pours. GPU batches are associated with their drawing rank, and the canvas retains its theme until layer/mode/UI-theme changes. Exclusions, hidden layers, fill toggles, deletions and theme/rank changes invalidate the affected data.

On the same ignored 34,145-object board, warm render-group assembly fell from about **18.4 ms to 3.35 ms median** (15 measured edits after warm-up). Scene update remained about **2.18 ms median**. An isolated headless WebGL check measured **63,481,228 bytes** for the initial full upload and **324,940 bytes in one upload** for a later small track edit. Eight edit samples reported about **7.7 ms median CPU** for scene update, assembly and buffer packing/submission together. These numbers exclude GPU completion/presentation and do not establish native FPS.

Cold draw preparation is still dominated by pours with thousands of holes. A separate profile spent about 7.3 seconds in zone geometry on this fixture; headless load/check timings varied around six seconds. Cold triangulation remains a future optimization, and native input responsiveness still needs home-laptop acceptance.
