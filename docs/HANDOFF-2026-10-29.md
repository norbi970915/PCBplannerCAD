## Causes and fixes

### Independent board items

- Twenty-seven proposed removals were explicitly marked board-only in the source. Another was a graphic-only footprint excluded from both BOM and placement output. The importer had discarded these distinctions.
- `PlacedFootprint.boardOnly` now persists retention intent, defaults to false for older documents and is omitted when false. Schematic synchronization keeps an independently placed footprint when it is absent from the schematic.
- Graphic-only retention inference requires both source exclusions and no numbered pads; ordinary electrical test points are not silently classified as independent graphics.
- Board Properties offers **Keep if absent from schematic**. This prevents schematic-driven removal, not deliberate manual deletion.

### Bus and scalar hierarchy connectivity

- Source bus aliases are preserved as per-sheet schematic metadata and saved/reopened with the native document. Definitions are collected across the project; inconsistent definitions are diagnosed instead of silently choosing one.
- Vector and group buses resolve individual scalar members across sheet boundaries. Different group prefixes map by relative member name; vector ports map by index. Nested members and alias expansion have bounded depth/member counts.
- Bus graphics remain separate from electrical wires. Crossings need a junction; touching endpoints and T connections join bus components. P and N remain separate nets.
- Conflicting bus labels, disjoint connected definitions, invalid alias expansion and ambiguous unjoined port crossings produce ERC errors. Quoted/escaped literal bus-name syntax is not yet implemented and produces an explicit diagnostic when recognized as a bus; this is not full source-format grammar coverage.
- A separate compiler bug kept local and hierarchical scalar labels with the same name apart within one sheet. They now join in that sheet's instance scope, without merging unrelated sheets.
- The audit's 46 previously split board nets are resolved. Twelve different generated-name spellings remain in the parity report; synchronized pad membership is preserved and they no longer propose pad-net edits.

### Placement and assembly flags

- All five apparently missing source parts were explicitly excluded from the board. Those source flags are now retained as hidden native fields and honored by synchronization, so these parts no longer create missing-footprint warnings or placement proposals.
- BOM exclusions and not-fitted metadata are retained in schematic import; board BOM/placement exclusion attributes and not-fitted metadata are retained in board import.
- BOM-only exclusion and placement-only exclusion affect their own assembly output. Explicit not-fitted parts remain absent from both. Schematic BOM output honors its exclusion field.
- Repeated import of two existing small projects again produces zero unexpected synchronization actions, including their exclusion metadata.

### Safe reviewed updates

- Split-net situations get a bus/hierarchy review diagnostic rather than being disguised as cosmetic renaming.

## Routing and length tuning — 2026-10-29 10:41

### Fixes implemented locally

- Tuning validates each bump at the actual proposed height and rechecks the complete rounded result. The old algorithm checked a full-height shape and later shrank it without checking the changed geometry; a small foreign pad could then intersect the final route. A regression reproduced that failure before the fix.
- Amplitude is a maximum. The planner tries smaller heights on both sides when full-height meanders do not fit. Width/clearance spacing, invalid/duplicate segments and locked tracks are validated before planning. The bounded, greedy search can still reject a feasible layout; it is not a general optimal router.
- Existing same-net via, pad, arc and track contacts on a selected segment are protected. Tuning cannot remove the source span under an interior via or fixed branch, or shortcut into nearby same-net copper. A disconnected interior-via regression failed before the fix and now passes.
- Poured copper is regenerated around the new tracks rather than blocking the preview. Keepouts, foreign pads/tracks/vias and the outline still constrain it. Apply uses a routing transaction, so dependent pours and removed teardrops recover with the tracks in one Undo/Redo. A pour regression checks clearance, exact saved-data recovery and reopen.
- Apply recomputes natively and compares against the exact geometry shown in the dialog before editing. Changed previews fail without partial edits or history. A target already within the 0.5% tolerance keeps the original IDs and saved/undo state.
- Tuning preview jobs are debounced with at most one native request in flight and only the latest request queued. Cancelled/obsolete results, failures and document reloads cannot replace the current preview. This suppresses stale deliveries; it does not forcibly abort a running native IPC request.
- Differential routing retains the previous partner endpoint across clicks and Backspace. A bounded turn connection preserves both starts where possible; turns requiring backtracking are rejected. Both members are checked against obstacles and against the required pair gap. Invalid/inconsistent plans cannot apply one member or leave shove edits behind. Blocked-start messages identify the conflicting copper.
- Route preview replies are invalidated by board/footprint/reload changes and changed route settings. Length feedback subtracts a shove source once when it becomes several replacement segments. Rule results are scoped to the current document/settings; invalid target bounds or lengths cannot display an in-range result.
