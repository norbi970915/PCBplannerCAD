# PCBPlannerCAD progress — 2026-10-26

## Continue on another computer

The source is in the repository's `main` branch. Clone or pull it, install the prerequisites listed in README.md, and run these commands from the repository root in PowerShell:

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd -C app test:editor
pnpm.cmd typecheck
pnpm.cmd dev
```

Use `pnpm.cmd build` for a standalone executable and Windows installers. Build outputs and dependencies are ignored by Git. Personal PCB projects are separate from the application source and are not included in this repository.

## Completed today

- Renamed the application, native executable, installers, package names and source folder to PCBPlannerCAD. Existing native design files remain readable.
- Published the application source to `main`. Public documentation describes PCBPlannerCAD directly. Internal session handoffs and audits remain local and ignored.
- Added repeated free-angle polygon Cut, Slice and Reshape tools. Cuts can begin on newly created diagonal boundaries. Outline edits and dependent copper refill share one undo transaction.
- Added an empty-selection **Properties / View** switch for board and footprint editors. Selecting an object continues to show its editing properties.
- Added layer visibility, Show all, Active only and Reset view controls.
- Added independent component-reference, component-value, pad-number, pad-net-name and other-text visibility controls, plus tracks, vias, pads, graphics, unrouted connections and DRC marker controls.
- Added **Snap to grid** and **Show grid** options. The idle selection cursor is free even while grid snapping is enabled. Grid snapping can be disabled for placing and dragging too. Polygon gestures retain their free-angle behavior.
- View preferences are local display settings, not design modifications or undo steps. They persist on the current computer and initialize subsequently opened documents.

## Navigation performance changes

Pointer samples are coalesced into one update/draw per animation frame. Pending motion is flushed before click/release events so drag endpoints remain accurate. Board geometry stays on the GPU when hover, selection or net highlights change; a small per-item tint table supplies the highlight instead. DRC and unrouted-connection geometry is cached across cursor movement and panning. The 2D canvas no longer requests preserved drawing buffers.

A read-only benchmark on a saved 5,169-object board counted 47,346 line segments and 136,254 fill vertices. The previous whole-scene hover rebuild cost about 4.1 ms median; the new sparse CPU highlight preparation measured about 0.005 ms median (0.028 ms at the 95th percentile). These are CPU measurements of this path, not a measured application FPS or a guarantee for other hardware.
