# PCBPlanner Studio — home-PC handoff — 2026-10-30

Source version: **0.6.6**. Delivery target: **main**. This handoff supersedes older progress notes for the changes below. Read AGENTS.md before continuing. This is a source-code handoff and local review build, not a public application release or a claim that every editing workflow is finished.

## Changes delivered

### Identity, libraries and distribution preparation

- Personal publisher: Buchmüller Norbert, contact pcbplanner.info@gmail.com. Product: PCBPlanner Studio, executable PCBPlannerStudio.exe, identifier com.pcbplanner.studio. Earlier identifiers are retained only for compatible migration; existing data is not overwritten.
- Added application terms, privacy information, source availability, third-party notices and an offline legal UI. Notices and five exact MPL source archives are generated from the locked installed dependencies and packaged by the build hooks. Generated resources are ignored by Git and must be regenerated on a fresh PC.
- STEP previews are temporarily omitted by owner decision. VRML previews and the independent native STEP exporter remain. Do not add the removed preview engine back without a separate review.
- The bundled Basic library is originally generated. Imported library notices are preserved; importing content does not grant redistribution rights. Files requiring library notices or DRC approvals use newer format versions, and older executables refuse them rather than silently dropping the metadata.
- Installer templates explicitly set desktop/Start/uninstall icons. Their pinned upstream provenance and required notice are included. The launcher is now Start-PCBPlanner Studio.cmd, matching README instructions.

### DRC, rules and editing controls

- Added a DRC sidebar tab beside Properties and View. Manual checks focus it; online checks update without stealing focus. Findings support search, severity filtering and paging, including reports beyond the old display limit.
- DRC findings can be approved into a collapsible Approved list and restored. Approvals persist with the board and apply only to the exact finding, relevant geometry and rules. Changed geometry/rules invalidates an old approval. Approval never disables native routing constraints or raw DRC.
- Rule editing explains first-match priority, validates inputs and preserves rejected/stale drafts. Routing defaults now use the same native rule resolution as DRC.
- R rotates components; right/middle drag pans during routing and movement. Right release does not rotate, cancel or prematurely place an object. Explicit side flipping remains available.

### Track/component movement and routing width

- Replaced the old JavaScript connected-copper planner with native geometry. Track dragging adjusts nearby bends first, preserves the distant route corridor and expands the affected section only when needed.
- Single straight-segment slides and connected two-segment corner moves protect fixed anchors, branches, locked copper and existing electrical connections. New paths reject crossings and acute reversals; repeated moves are checked for bend/segment growth. Component/via moves rebuild attached sections while preserving connections.
- Native previews are bounded to one live request plus the latest queued pointer position. Continuous movement shows the last completed valid plan while a newer target is checked. Placement still requires the exact current target. Escape, source changes and settings changes invalidate incompatible replies.
- Blocked placements reuse one notification instead of stacking warnings. The nearby-window rejection is retained instead of being replaced by an unrelated distant fallback error.
- Starting routing on a straight or curved track automatically adopts that track's exact width, including either endpoint or an interior branch start. A pad/via with one unambiguous connected straight-track width inherits it too; mixed-width junctions fall back to the existing setting/rules instead of guessing.
- W / Shift+W and the width field can override an inherited width; 0 restores the rule width. Finishing restores the earlier width setting unless the user changed it. The routing hint shows three decimal places in millimetres so 0.254 is not presented as 0.25.

## Continue at home

Use a clean checkout, or keep any existing home-PC edits on their own branch before updating. From the app repository:

~~~powershell
git fetch origin
git switch main
git pull --ff-only origin main
pnpm.cmd install --frozen-lockfile
cargo fetch --locked
pnpm.cmd -C app legal:prepare
pnpm.cmd typecheck
pnpm.cmd -C app test:editor
cargo test --workspace --offline
pnpm.cmd dev
~~~

Tested toolchain on the work PC: Node 24.19.0, pnpm 12.15.0, rustc/cargo 1.99.1, Windows MSVC. Install the Visual Studio C++ build tools and WebView2 runtime as described in README. The dependency-fetch steps above are necessary before offline legal generation on a fresh machine. Do not copy generated notices from an older lockfile.

For a standalone installation:

~~~powershell
pnpm.cmd build
~~~

Install the new current-user setup from target/release/bundle/nsis/PCBPlanner Studio_0.6.6_x64-setup.exe after saving and closing any running Studio window. The matching MSI is in the sibling msi directory. Distribute complete packages with their legal resources, not a bare executable.

### Optional browser checks

The harnesses use an external Playwright package and Microsoft Edge. To reproduce the work-PC checks without changing the app dependency lockfile:

~~~powershell
$studioBrowserTools = Join-Path $env:LOCALAPPDATA 'PCBPlannerTools/browser-tests'
npm.cmd install --prefix "$studioBrowserTools" --no-save --package-lock=false playwright-core@1.63.0
$env:PCAD_PLAYWRIGHT_PATH = Join-Path $studioBrowserTools 'node_modules/playwright-core'
pnpm.cmd -C app test:interactions
pnpm.cmd -C app test:projects
pnpm.cmd -C app test:docking
~~~

The app source and this document are in Git. User designs, private reference boards, unsaved work, profiles, recovery data, local audit logs and compiled installers are not. Move an authorized project folder separately if it is needed at home; no private board has been added to the app repository.
