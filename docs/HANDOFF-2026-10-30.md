### Track/component movement and routing width

- Replaced the old JavaScript connected-copper planner with native geometry. Track dragging adjusts nearby bends first, preserves the distant route corridor and expands the affected section only when needed.
- Single straight-segment slides and connected two-segment corner moves protect fixed anchors, branches, locked copper and existing electrical connections. New paths reject crossings and acute reversals; repeated moves are checked for bend/segment growth. Component/via moves rebuild attached sections while preserving connections.
- Native previews are bounded to one live request plus the latest queued pointer position. Continuous movement shows the last completed valid plan while a newer target is checked. Placement still requires the exact current target. Escape, source changes and settings changes invalidate incompatible replies.
- Blocked placements reuse one notification instead of stacking warnings. The nearby-window rejection is retained instead of being replaced by an unrelated distant fallback error.
- Starting routing on a straight or curved track automatically adopts that track's exact width, including either endpoint or an interior branch start. A pad/via with one unambiguous connected straight-track width inherits it too; mixed-width junctions fall back to the existing setting/rules instead of guessing.
- W / Shift+W and the width field can override an inherited width; 0 restores the rule width. Finishing restores the earlier width setting unless the user changed it. The routing hint shows three decimal places in millimetres so 0.254 is not presented as 0.25.

## Snapshot routing backend update — local only

The native application now uses a persistent routing engine per board snapshot for single routes, pairs, track drags, connected moves and paired transitions. The routing pool keeps up to three boards, each with bounded target history and immutable shared layer indexes. Source geometry and footprint-cache changes invalidate the snapshot. Every solve receives a fresh overlay; failed edits cannot contaminate later requests, and revisiting a reviewed target restores its exact plan. Geometry indexes, physical copper and pad geometry are shared where source identity is valid. Different board windows do not hold one global routing lock during solving.

Conductor topology now includes interior T-junctions and vias, using a spatial index. Explicit arm dragging splits virtual junctions only inside a speculative board and expresses the result as one checked edit against original identities. Branches and layer transitions remain fixed. Tiny necks inside lands are followed toward the real fixed center, so the drag calculation includes their departure direction. Shove can expand from a short colliding segment into connected conductor windows instead of pinning every neighboring bend. Locked and branched foreign conductors remain fixed boundaries when their safe displacement is unavailable. Failed overlay branches are rolled back.

Walkaround now tries clearance-contour vertices before its grid fallback. All launches, conductor windows and fallbacks share a deterministic 6,000-unit preview-search allowance. Exhausted searches retain checked partial geometry and explicitly report the limit; the allowance is a work bound, not a guaranteed wall-clock deadline. Direct paths and final DRC remain authoritative. Via candidates first undergo indexed, rule-specific copper checks across their physical spans before expensive full-board-copy checks. The canvas reuses its static scene while successive previews affect the same excluded objects. View, layer, document, cache and source changes still trigger rebuilding.
